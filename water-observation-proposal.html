01 / Diagnosis

The observation vocabulary is too narrow.

Add a supported path for observing scenery from interpretation through narration. The issue spans the scene data, target choices, validation, and directive selection; editing the wording of the clarification would leave the underlying failure intact.

Confirmed in the current code

Water cannot be represented.

The scene lists only key, ledger, and bell. Jev is told that an inspection examines those three objects, and that an unsupported physical action is unclear. The target enum and decoder also admit only those objects, none, and unknown.

Sources: scene_constants.py:6–23; question_constants.py:35–52, 87–93; decisions.py:37–43; decoder.py:21–34.

Confirmed in the trace and replay

The narrator never gets a description task.

Python rejects the interpretation before resolving an action. It selects the scripted clarify directive, and Bonsai returns its fixed fallback without a generation request. This was neither a Bonsai outage nor a generated refusal.

Sources: validation.py:18–24; turn.py:21–23; bonsai.py:110–120; convgame.log:345–384, 698–743.

Scope of the conclusion. The two Jev outputs differ, but both fail at the same validation gate. The missing supported target is a structural defect. Prompt changes may improve model classification, but these two samples do not establish a general grammatical bias against imperative or first-person commands.

03 / Proposed implementation

A small observation path with shared scene data.

Implement the following as one coherent change. Reuse the existing inspect action and quiet Narrator behavior. A full general-purpose action engine is unnecessary for this problem.

1

Define observable targets in the world layer.

Introduce a small, network-free scene catalog, for example convgame/world/scene.py, containing the existing three objects plus water. Each entry needs a stable ID, aliases, visibility conditions, observable facts, a fallback description, and an optional existing mechanical effect.

Explicitly author whether the harbor water can be seen through the office window. The current scene mentions a storm and danger on the water, while Maren calls the water “ugly”; it does not define a visible water target or detailed water facts. Treat window visibility as proposed scene content, rather than an established fact from this log.

Build inspection choices and decoder allowlists from this same catalog. Keep the spoken object question separate: expanding its current shared enum would also permit ask_water and other events that have no directive. Scenic observations should not accidentally become item requests.

Change locations: scene_constants.py, questions.py:25–31, decoder.py, decisions.py. Only the inspection target needs the broader set of IDs.

2

Make the two literal forms deterministic.

Add a narrow whole-line recognizer at the interpretation boundary for plain, unquoted observations of registered targets: Look at <target> and I look at <target>, with case, surrounding whitespace, an optional article, and final punctuation normalized. Both produce the canonical observation shown below, with no speech or emotional signal.

Use this local path only for complete matches to catalog aliases. Inputs addressed to Maren, quoted speech, private thoughts, future plans, compound actions, and additional clauses still go through Jev. Do not globally strip “I”, or override uncertain arbitrary model output based on a substring match.

Broaden Jev’s inspection criteria to registered observable scenery as well as objects, and add paired examples for richer wording. Explicitly distinguish Look at the water from Maren, look at the water and I think about looking at the water. Retain confidence checks for model-interpreted commands.

Change locations: decider.py:27–43, question_constants.py:20–59. This proposal gives plain observations zero Jev calls; other inputs retain one batched call. Update the current one-call documentation and log the local interpretation explicitly.

3

Resolve scenery to a contextual Narrator directive.

Validate that the inspection target belongs to the current catalog and is perceptible. Preserve existing ledger, key, and bell behavior. Route other registered targets to a reusable inspect_scenery directive carrying the resolved target and its allowed facts, rather than using every target ID as a key into DIRECTIVES.

Water inspection consumes one turn under the existing rules. It does not mark the ledger read, agree a plan, ring the bell, award the key, or change Maren’s mood. An unseen known target gets a concrete Narrator limitation; a missing or ambiguous referent gets a focused clarification. Unsupported actions should get a specific limitation where possible.

Add the new observation event to ACTION_EVENTS so a final-turn water description is retained before the timeout. Keep it out of SPEECH_EVENTS and GUIDANCE_EVENTS, so it is narrated without inventing player speech. Existing narrated-outcome memory can retain the response.

Change locations: validation.py, actions.py:46–64, directives.py, directive_constants.py:142–150, outcomes.py:40–60. Keep emotions.py:14–18 quiet-inspection behavior.

4

Supply facts first, then controlled atmosphere.

Pass the resolved observation context to Bonsai even when untrusted_player_line is empty. The current empty field is appropriate for unspoken actions, but the new target and facts must travel in the authoritative directive or a dedicated observation payload.

Prefer explicit, currently observable scene facts. Where detailed facts are absent, select from authored atmospheric descriptions compatible with the target and storm setting; this allows generic random variation without inventing mechanics. Randomize presentation, never visibility, possession, route safety, or objective state.

Bonsai may phrase those supplied details within the existing speaker, sentence, and word limits. Keep a useful scripted observation fallback for service failures. Its current prompt forbids inventing facts, so supply permitted atmospheric details explicitly rather than expecting the model to improvise them against that instruction.

Change locations: bonsai.py:12–32, 115–128, observation directive construction, and cli.py:100–120 for fallback and logging integration. Existing structural output validation does not prove factual accuracy; supplied facts and constrained fallback text remain essential.

Partial fixes to avoid. Lowering the 0.60 floor would turn the first logged none into unspoken guidance, while unclear would still block the second. Adding only a water enum or prompt example leaves the resolver and directive gaps. Sending rejected input directly to Bonsai leaves the target unresolved and lets prose imply unvalidated outcomes.

PYTHONDONTWRITEBYTECODE=1 .venv/bin/python - <<'PY'
import re
from dataclasses import fields
from pathlib import Path
from convgame.world import Decisions, Pick, World, advance

log = Path('logs/convgame.log').read_text()
lines = re.findall(
    r'\] turn.started:[^\n]*\n  player_line: ([^\n]+)', log)
blocks = re.findall(
    r'\] world.interpretation:[^\n]*\n  answers:\n(.*?)\n  before:',
    log, re.S)
assert len(lines) == len(blocks) == 2
failures = []
for line, block in zip(lines, blocks):
    values = {}
    for field in fields(Decisions):
        match = re.search(
            r'^    ' + field.name +
            r':\n      value: (\S+)\n      confidence: ([\d.]+)',
            block, re.M)
        if match:
            values[field.name] = Pick(match[1], float(match[2]))
        else:
            values[field.name] = float(re.search(
                r'^    ' + field.name + r': ([\d.]+)',
                block, re.M)[1])
    _, directive = advance(World(), Decisions(**values))
    text = '\n'.join(x.text for x in directive.fallback)
    print(f'{line!r} → {directive.event}: {text}')
    if 'Your intention is unclear' in text or 'water' not in text.lower():
        failures.append(line)
assert not failures, f'Expected water information; failed: {failures}'
